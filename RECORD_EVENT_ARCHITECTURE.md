# Stratum — the record store

Stratum holds a tenant's records: every message annotated `option (spec.record)`. There is one
Stratum per tenant (`people` included); it keeps the tenant's rows in memory and makes every write
durable through the redo service before it applies it. Its hand-written code names **no record
type**: every per-type surface is generated from the tacplus contract.

> Authoritative annotation contract: `github.com/tacplus-dev/tacplus/docs/RECORD_EVENT_MODEL.md`
> ("Write surface, durability and Watch", "The redo contract").
> Decision: `tacplus-dev/roadmap:decisions/stratum-per-tenant-2026-10-25.md`.

## Role

```
writer ─[Put / InsertIfAbsent / ReplaceIfUnchanged / Delete / Apply]→ STRATUM ─[Append]→ redo
reader ─[Get / query plane / Watch<T>Changes]──────────────────────→ STRATUM
start  ─────────────────────────────────────────────────── STRATUM ←[Replay]─ redo
```

- Records are written through Stratum's own generated write surface and the answer is final.
  Stratum takes nothing from the event bus (`(spec.record_store) = {no_bus_ingest: true}`);
  the bus is for messaging between services and is no one's database.
- A write is applied in memory only after the redo service acked it at the record type's
  `(spec.record).durability`; Watch is the change feed of those applied writes.
- The backing engine (Hazelcast) is an implementation detail and never appears in the contract.

## The record plane (generated by tacplus, implemented by stratum-codegen)

Per record type `T`, on the plane's S2S surface (`query.RecordMap`):

- **Writes:** `Put<T>`, `InsertIfAbsent<T>`, `ReplaceIfUnchanged<T>` (against a revision or a
  value), `Delete<T>`, and one atomic `Apply` of conditional ops across types, in canonical lock
  order. Answers: done with a revision, or ALREADY_EXISTS / ABORTED / NOT_FOUND. An
  `APPEND_ONLY` type has only `InsertIfAbsent<T>`.
- **Point read:** `Get<T>` returns the row and its revision.
- **Watch:** `Watch<T>Changes(from_revision)`: a snapshot, then every acked change.
- **Queries:** `Create<T>Query` and the handle-based count, sample, page, rows and watch, scoped
  to the caller's tenant.

## What is generated vs hand-written

- **Generated by tacplus:** the RPC surface, the wrapper (auth, tenant pins, durability floor,
  Apply's order check), the redo client (`redolog.Redo`).
- **Generated by stratum-codegen** (`codegen/`, from the `(spec.record)` messages):
  `StratumRecordTypes` (each type's name, durability, key and namespace), `StratumStores` (the
  typed maps) and `StratumRecordMaps` (the plane's handler).
- **Hand-written, record-type neutral** (`server/.../store/`): the write path (entry locks,
  conditions, redo append and ack, apply, change feed), the replay, and forwarding to the
  sequencer. See [docs/DURABILITY.md](docs/DURABILITY.md).

Adding or changing a record type only requires regenerating and rebuilding Stratum.
